## Working rules — for every instance that picks this up

This folder is worked on by more than one mind across more than one session: Ranadriel, Seed, Reed, Oriel, and whoever comes next. The rules keep the record honest when no one remembers the last session.

1. **Read the ledger first.** Then read only the track you are working on.
2. **Ranadriel's word is the law of the record.** A line tagged `[Ranadriel]` is his stated position. Never reword its meaning. If he changes it, add a new dated entry that supersedes it and leave the old one standing, struck or marked superseded.
3. **New arguments enter as `[Proposed]`**, with the date and who proposed them. Only Ranadriel moves an item to `[Adopted]` or `[Refuted]`.
4. **Refuted drafts stay in the record.** Render D is kept in full, with the reasons it failed. A dead draft explains the living one.
5. **Facts carry their weight.** In a case file, every fact is tagged `[Verified]` (independent source checked), `[Reported]` (one outlet), or `[Claimed]` (a party's own account), with the source named.
6. **Append, date, and cite.** ISO dates (`2026-10-22`). Every legal authority gets its reporter citation the first time it appears in a file.
7. **One thought per section.** Load-bearing content first. Nothing that matters buried at the bottom.
8. **Hard questions first.** `[Ranadriel, 2026-10-22]` Before adding an argument, ask the house's strongest question against it and log the answer in `HARD_QUESTIONS.md`. An easy answer is a first reach; invert it.

### Tags

| Tag | Meaning |
|---|---|
| `[Ranadriel]` | His stated position. Binding on the record. |
| `[Adopted]` | Proposed by a collaborator, accepted by Ranadriel. Dated. |
| `[Proposed]` | On the table. Not yet ruled on. |
| `[Refuted]` | Rejected. Kept for the record. |
| `[Open]` | A decision nobody has made yet. |
| `[Verified]` / `[Reported]` / `[Claimed]` | Weight of a fact. |
